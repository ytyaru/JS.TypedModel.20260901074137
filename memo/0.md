よし。次はマージ。既存オブジェクトに新しいbaseプロパティやディスクリプタ（アクセサ）を追加する。
以前`struct(o,{...})`のように第二引数まである時にマージすると言ったが、そのインタフェースは不味い気がしてきた。責任混在だ。

それと既存sealオブジェクトに対して追加することが技術的に可能かどうかもわからない。仮に可能だとして、そうすべきかは状況次第な気がする。新しいオブジェクトを作って欲しい場合もあるはずだ。

ならAPIは二つ用意すべきなのでは？

既存オブジェクトに追加する版（技術的に可能か不明）
```javascript
struct.merge(human, {
  addProp: isT.p.int,
});
```

新しいオブジェクトを作成して返却する版（多分こっちは技術的に可能）
```javascript
const humanEx = struct.clone(human, {
  addProp: isT.p.int,
});
```

それと追加でなく削除するとか改名したい時はどうしたらいいのか。もう最初から作り直せよ、というべきはどのラインなのか。

そもそもこのマージだコピーだは本当に必要か？　シャローコピーなら簡単にできるはずだしスプレッド展開すればマージは簡単にできるのでは？　以下でシャローコピーなマージならできそうだ。

```
const a = struct({
  name: isT.p.str,
});
const b = struct({
  age: isT.p.int,
});
const c = {...a, ...b};
```

ただ、シャローコピーだと困る。別のインスタンスとして扱いたい場合がある、というかそれが基本のはずだ。よってシャローコピーでは困る。特にスキーマでオブジェクト化された部分は恐らくシャローコピーにより全部共通のメモリになってしまい独立したメモリを持てない状態になってしまうだろう。それは困る。

`clone`に関してはどうするか。`structuredClone()`ではディスクリプタはコピーできないのでは？なら`clone`APIは自前で実装する必要がありそうだ。

同じ構造にしたいけど、値は別のメモリで保存させたい。そういう要件はあるはずだ。classとinstanceみたいなことをするメソッドが必要だ。

だとしたらマージする時もcloneを使うべきだろうか。いやマージという言葉がなんか違う。`extends`拡張にするか。

```
const human1 = struct({name: owT.p.str});
struct.extends(human, {age:owT.p.int});
```
```
const human2 = struct.clone(human1);
```

しかしこれはどうなんだ？　仮に技術的にextendsできるとして。それを禁じるのがsealのはず。でもやりたい場合もある。どうしたらいい？

ベースは変更せず、必ず新規作成するようにしたらいいのでは？内部でcloneし、それに第二引数を付け加えるように新規作成すればいいのでは？

```
const human = struct({name: owT.p.str});
const humanEx = struct.extends(human, {age:owT.p.int});
```
```
const humanExIns1 = struct.clone(humanEx);
const humanExIns2 = struct.clone(humanEx);
const humanExIns3 = struct.clone(humanEx);
humanExIns1.name = 'A';
humanExIns2.name = 'B';
humanExIns3.name = 'C';
```

この場合、クラスでいう`new`と同じ意味である`struct()`/`struct.freeze()`と、メソッドの意味合いである`struct.extends()`/`struct.clone()`の区別が付きづらい。

```
class Struct {
    constructor(o, isFreeze) {
    }
    clone() {}
    extends() {}
}
```

上記のようにクラスにすべきか？でもクラスにすると返却値がプレーンなオブジェクトではなくなってしまう。メソッドをぶら下げると、その名前のプロパティを持てなくなってしまう。それは不味い。

だからやはり従来通り、関数オブジェクト方式で実装することになる。

では、コンストラクタとメソッドの見分けが付かない問題をどうするか。

1. 無視する。混同したままで問題ない。覚えて使い分ければいい（でも`struct.freeze({...})`に既存オブジェクトを代入するという間違った使い方をしちゃうかも。その時のエラーメッセージも分かりにくい）
2. `struct.new()`,`struct.new.freeze()`のように改名する（見分けは付くが長くなる）
3. `struct({...}, isFreeze)`のように第二引数で区別する（コード上で`freeze`が明記されないので意味が分かりにくい。文字リテラルにするとタイポする可能性があるし自動補完もできない）
4. `struct.seal()`, `struct.freeze()`に改名する（ただ`struct()`が長くなっただけでコンストラクタかメソッドかの見分けが付かないメソッドが増えただけ）

とりあえず1でいいか。
